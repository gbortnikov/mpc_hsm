# Node Refactoring Summary

## Что было улучшено

### 1. **Архитектура приложения**

#### До рефакторинга:
- Вся логика в `main.go` (309 строк)
- Инициализация компонентов разбросана по коду
- Нет централизованного управления жизненным циклом
- Сложно тестировать

#### После рефакторинга:
- `main.go` — всего 35 строк, простая точка входа
- Новый пакет `app/` для управления приложением
- Четкое разделение ответственности
- Легко тестировать каждый компонент

### 2. **Новая структура проекта**

```
apps/node/
├── main.go                    # Точка входа (35 строк)
├── app/
│   ├── app.go                # Application lifecycle manager
│   └── cli.go                # CLI флаги и конфигурация
├── server/
│   ├── server.go             # Основная структура сервера
│   ├── keygen_handler.go     # Обработчики keygen
│   ├── signing_handler.go    # Обработчики signing
│   ├── p2p_handler.go        # P2P методы
│   └── helpers.go            # Вспомогательные функции
├── middleware/
│   ├── logging.go            # Логирование запросов
│   ├── recovery.go           # Восстановление от паники
│   └── auth.go               # Аутентификация
├── logger/
│   └── logger.go             # Контекстное логирование
├── errors/
│   └── errors.go             # Структурированные ошибки
├── config/
├── db/
├── security/
└── tss/
```

### 3. **Application Lifecycle Manager**

**Файл:** `app/app.go`

**Возможности:**
- Централизованная инициализация компонентов
- Dependency Injection через структуру `Components`
- Graceful shutdown для всех компонентов
- Четкие этапы инициализации (Security → Database → gRPC)

**Использование:**
```go
app := app.New(config)
if err := app.Initialize(); err != nil {
    log.Fatal(err)
}
if err := app.Run(); err != nil {
    log.Fatal(err)
}
```

### 4. **Middleware система**

Добавлены три interceptor'а для gRPC:

1. **Recovery** — ловит панику и возвращает корректный gRPC ответ
2. **Logging** — логирует все запросы с временем выполнения
3. **Auth** — проверяет аутентификацию (интегрируется с mTLS)

**Порядок выполнения:** Recovery → Logging → Auth → Handler

### 5. **Улучшенное логирование**

**Файл:** `logger/logger.go`

**Возможности:**
- Контекстные логи с автоматическим извлечением request_id, session_id, party_id
- Структурированное логирование
- Легко добавить новые контекстные поля

**Пример:**
```go
ctx = logger.WithSessionID(ctx, sessionID)
logger.Info(ctx, "Processing message", "from", partyID)
// Автоматически добавит session_id в лог
```

### 6. **Структурированные ошибки**

**Файл:** `errors/errors.go`

**Возможности:**
- Коды ошибок для программной обработки
- Wrapping с дополнительным контекстом
- Детали ошибок для отладки

**Пример:**
```go
if err != nil {
    return errors.DatabaseError("failed to save share", err).
        WithDetail("session_id", sessionID)
}
```

### 7. **Модульная структура server package**

**До:** 1 файл на 981 строку

**После:** 5 специализированных файлов:
- `server.go` — структура сервера и конструкторы (220 строк)

### 8. **CLI и конфигурация**

**Файл:** `app/cli.go`

**Улучшения:**
- Отдельная функция для парсинга флагов
- Приоритет: CLI флаги → файл конфигурации → переменные окружения → defaults
